# NVT Signal 역추적 결과

## 결론

차트 https://www.tradingview.com/chart/X3L1Uw1v/ 의 두 번째 열 지표는 gliderfund가 게시한 보호 스크립트 **"NVT (original) - Network Value to Transactions"**(tradingview.com/script/50VFVta2)의 **버전 1**입니다. 스크립트 ID는 `PUB;mGO6NQAZK4oHjEzHPwWWWTIYWDGJkBQF`이며, 네 번째 열은 같은 스크립트의 버전 2(2024-11-05)입니다.

`nvt_signal_reconstructed.pine`은 이 지표를 Pine v6로 재구성한 코드입니다. 차트에서 원본과 재구성 코드의 plot 값을 봉 단위로 추출해 비교한 결과, 13개 경우(59,461행)에서 모든 plot 값과 na 위치, 색상이 10자리 유효숫자 수준까지 일치했습니다.

```
NVT = BITSTAMP:BTCUSD 종가 × QUANDL:BCHAIN/TOTBC / SMA(QUANDL:BCHAIN/ETRVU, 90)
```

- 이동평균은 데이터 심볼 자체의 봉(2009-01부터, 0 값 포함)으로 계산합니다.
- `Force Daily View`를 끄면 차트 시간 단위의 봉으로 계산합니다. 따라서 주봉에서는 90주, 월봉에서는 90개월을 평균합니다.
- 분봉 차트와 `Force Daily View`를 켠 경우에는 모든 값을 일봉에서 가져옵니다.
- 원본이 2011-08-18부터 시작하는 이유는 BITSTAMP 가격 데이터가 그날 시작하기 때문입니다.

## 확정된 규칙

| 항목 | 규칙 |
|---|---|
| 자동 기준선 (상단/하단) | 분봉 200/60, 일봉 계열 150/45, 주봉 계열 450/100, 월봉 1000/333. `Force Daily View`를 켜면 모든 시간 단위에서 150/45입니다. |
| 기준선과 캡 라인 표시 | NVT가 기준선을 넘었고, 해당 Highlight Background 옵션이 켜진 봉에서만 값이 있습니다. |
| 캡 라인 | 차트 봉 365개 구간의 NVT 최고값·최저값(na 제외)입니다. `bar_index < 364`이면 `상단 × 1.1`, `하단 / 1.1`을 씁니다. |
| NVT 선 색상 | 하단 미만 #00FF00, 상단 초과 #FF0000, 그 사이 #474747(Night Mode에서는 #00FFFF) |
| 채우기 색상 | 빨강·녹색, 투명도 90. Night Mode에서는 NVT가 상단을 넘은 봉에서 두 채우기 모두 흰색입니다. |
| 신호선과 교차 | `ta.ema(nvt, 13)`. crossover는 Bullish, crossunder는 Bearish이며, 점은 신호선 값 위치에 찍힙니다. |
| 라벨 | 마지막 봉의 NVT 위치에 "NVT"(labelup, tiny, 투명도 30) |

## 근거

1. **공개 메타데이터**: 입력값의 이름·기본값·순서·최솟값, plot 제목과 순서, 채우기, 색상 팔레트, 숨김 스타일, 라벨 투명도, 알림 6개의 제목과 메시지를 그대로 옮겼습니다.
2. **차트 값 대조**: 4H, 1D, 2D, 5D, 1W, 2W, 1M과 설정 조합 6가지(교차·라벨 표시, Night Mode, Highlight Background 끔, Highlight Areas 끔, Force Daily, Manual Levels)에서 원본과 재구성 코드를 비교했습니다. 불일치는 0건입니다.
3. **독립 데이터 재계산**: 차트와 별개로 확보한 Quandl BCHAIN 원본(QuantConnect 제공, 2009-01 ~ 2021-11)과 BITSTAMP 종가로 NVT를 다시 계산했습니다. 1D 3,737봉 중 3,733봉, 1W 535봉 중 533봉이 원본과 5e-10 이내로 같았습니다. 나머지는 데이터 파일 마지막 며칠의 수정치입니다. 차트 종가를 쓰면 중앙 오차가 0.15%, 최대 오차가 50%로 커지므로, 가격 기준은 BITSTAMP로 확정됩니다.

## 한계와 주의 사항

- **데이터 피드 상태**: `QUANDL:BCHAIN/ETRVU`와 `TOTBC`, 그리고 이름만 다르고 데이터가 같은 `BCHAIN:*` 피드는 2026-06-22 이후 한동안 새 봉이 없었습니다. 그동안의 NVT는 원본과 재구성 코드 모두 "BITSTAMP 종가 × 상수"였습니다. 2026-11에는 공백이 채워졌고, 하루 늦게 정상적으로 갱신되고 있습니다(아래 "리페인트 원인" 참고). TradingView 공식 레퍼런스에는 QUANDL 요청이 더 이상 유효하지 않다고 적혀 있으므로, 앞으로는 두 지표 모두 오류로 멈출 수 있습니다.
- **최종 수정분의 차트 실행 여부**: 차트에서 완전 일치를 확인한 것은 Cowork가 만든 v4입니다. 최종 코드는 v4에 메타데이터 항목(알림 6개, 입력 최솟값, 숨김 스타일, 라벨 투명도, precision 제거)만 더했습니다. 이 추가분은 plot 값에 영향을 주지 않지만, 차트에서 다시 실행해 보지는 않았습니다.
- **알림 조건**: 알림의 제목과 메시지는 메타데이터에서 가져왔지만, 조건식은 제목에서 추론했습니다. plot 값으로는 검증할 수 없습니다.
- **검증하지 않은 경우**: INDEX:BTCUSD 이외의 차트(특히 USD가 아닌 차트), 틱 차트, 3M 이상의 월봉(이동평균이 계산되지 않아 값이 없음), Highlight 옵션을 하나만 끈 경우, Night Mode와 Highlight 옵션을 함께 바꾼 경우입니다.

### 원인

NVT에 들어가는 세 변수 중 거래량(`ETRVU`)만 바뀌었습니다. 가격(BITSTAMP)은 바뀌지 않았습니다. 공급량(TOTBC)은 과거 값이 그대로이고 2026-06-22 이후의 공백만 채워졌으며, 이 효과는 9월 봉에서 +0.2%입니다. 코드는 바뀌지 않았고, 미래 데이터를 쓰는 문제도 없습니다. 당시 비어 있던 거래량 데이터가 나중에 채워지면서 값이 바뀐 것입니다.

- **월봉 계산 방식**: 월봉에서 거래량은 그 달 마지막 날 하루의 값이고, 지표는 이 값들의 90개월 평균을 분모로 씁니다. 하루 거래량은 요일에 따라 몇 배씩 다릅니다(예: 2025-09-28 일요일 45억 달러, 09-30 화요일 188억 달러). 그래서 그 달 마지막 데이터의 날짜가 바뀌면 그 달 값이 크게 달라지고, 그 차이가 이후 90개 월봉에 영향을 줍니다.
- **2026-09 봉 (피드 중단)**: 9월에는 거래량과 공급량 데이터가 2026-06-22에서 멈춰 있었습니다. 그래서 6~9월 봉은 6월 봉의 평균을 그대로 써서 "BITSTAMP 종가 × 0.0040700818"이었고, BTC가 81,817달러를 넘으면 333을 넘었습니다. 데이터가 채워진 뒤 9월 봉의 분모는 11.2% 커졌습니다.
  - 7~9월 말 값(140억, 94억, 102억 달러)이 평균에 들어오고 2019년 1~3월 값(4억~9억 달러)이 빠졌습니다: +7.1%
  - 6월 말 값이 06-22 값(50억 달러)에서 06-30 값(135억 달러)으로 바뀌었습니다: +1.9%
  - 아래 세 달의 월말 날짜 변화: +2.3%
  - 그 밖의 과거 값 수정: -0.1%
- **2026-01 봉 (월말 날짜 누락)**: 9월 당시 데이터에는 2025-09-29·30, 2025-10-30·31, 2026-01-31 값이 없었던 것으로 보입니다. 그래서 그 달의 마지막 값이 하루나 이틀 앞 날짜의 값이었습니다. 지금은 이 날짜들이 채워져서 1월 봉의 분모가 2.26% 커졌습니다. 세 달의 변화만 반영하면 1월 봉은 326.97이고, 나머지 수정만 반영하면 335.32로 여전히 333 위입니다.

  | 달 | 9월 당시 월말 값 | 지금 월말 값 | 1월 봉 분모에 준 영향 |
  |---|---|---|---|
  | 2025-09 | 28일(일) 값, 45억 달러 | 30일(화) 값, 188억 달러 | +3.4% |
  | 2025-10 | 29일(수) 값, 130억 달러 | 31일(금) 값, 152억 달러 | +0.5% |
  | 2026-01 | 30일(금) 값, 148억 달러 | 31일(토) 값, 86억 달러 | -1.5% |

- **과거 값의 작은 수정**: 과거 거래량 값도 주로 2016~2023년에 걸쳐 조금씩 수정되었습니다(중앙값 0.25%). 그래서 닫힌 월봉 120개(2016-06 ~ 2026-05)가 -4.0% ~ +1.6% 바뀌었고, 2016-12 봉도 333 아래로 내려갔습니다.

### 근거

- 2026-09-25에 차트에서 추출한 월봉 값(124개월)을, 2026-11-12에 받은 데이터로 다시 계산한 값과 비교했습니다. 2026-11에 차트에서 실행한 원본 값은 재계산 값과 124개월 모두 일치했습니다.
- 거래량이 바뀌면 그 달의 차이가 90개월 평균에 들어갔다가 90개월 뒤에 반대 부호로 빠져나갑니다. 실제 차이가 이 모양으로 나타났습니다(상관계수 -0.9999). 가격이나 공급량이 바뀌었다면 해당 달에만 차이가 생겼을 것입니다. 차이가 거의 없는 달에서는 가격과 공급량이 백만분의 1 수준까지 같았습니다.
- 9월 당시 월말 값을 역산하면, 2025-09는 09-28 값, 2025-10은 10-29 값, 2026-01은 01-30 값과 0.03~0.12% 이내로 일치합니다. 같은 방법으로 역산한 2026-06의 월말 값은 06-22 값과 0.07% 이내로 일치하며, 이는 피드가 06-22에서 멈췄다는 사실과 맞습니다.

### 현재 상태 (2026-11-15 확인)

- 거래량과 공급량은 하루 늦게 정상적으로 갱신되고 있습니다(11-14까지).
- 11-12 이후 3일 동안 과거 거래량 값은 하나도 바뀌지 않았습니다. 공급량은 당시 최신일이던 11-11 값만 보완되었고(+0.001%), 닫힌 월봉 125개의 값은 같았습니다.
- 가장 최근 하루는 나중에 조금 보완될 수 있습니다. 진행 중인 월봉은 그날 들어온 하루 거래량으로 매일 다시 계산됩니다.

### 확인하지 못한 것

- 데이터가 채워진 시점: 2026-09-26 이후, 2026-11-12 이전이라는 것만 확실합니다.
- 수정 주체: 원래 제공처인 blockchain.com인지 TradingView 쪽인지 데이터만으로는 구분할 수 없습니다.
- 월말 날짜 누락: 9월 당시 일별 데이터가 남아 있지 않아 직접 확인하지 못했고, 월말 값으로 추론했습니다.

## 4열 지표 (같은 스크립트의 v2)

4열은 같은 스크립트의 버전 2(2024-11-05)입니다. 작성자가 Quandl 대신 온체인 전송량을 쓰도록 바꾼 버전이며, `nvt_signal_v2_reconstructed.pine`으로 재구성했습니다.

```
NVT = GLASSNODE:BTC_MARKETCAP / SMA(GLASSNODE:BTC_TOTALVOLUMEUSD, Transaction Period)
```

- 두 값 모두 차트 시간 단위의 봉으로 가져옵니다. 1D 6,109봉, 1W 836봉, Transaction Period 30인 1D에서 모두 원본과 일치했습니다.
- Glassnode 데이터는 약 2일 늦게 갱신되므로, 마지막 봉 몇 개는 같은 값이 반복됩니다.
- 분모인 Glassnode 총 전송량은 blockchain.com 추정 거래량(ETRVU)보다 대체로 5~10배 큽니다. 그래서 값의 크기가 v1의 약 1/10이고, 45/150 같은 v1 기준선은 적용되지 않습니다.
- 알림의 조건식과 메시지, `Force Daily View`의 동작은 추정입니다.

- `nvt_signal_v2_reconstructed.pine`: 4열(v2)을 재구성한 Pine v6 코드입니다.
