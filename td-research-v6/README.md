# TD Research v6 종합 해설서

스크립트: [`kidze_td_research_v6.pine`](kidze_td_research_v6.pine) · Pine Script v6 · 2026-10-31

기존 [`TD Sequential`](../td-sequential/)과 별도로 설치하는 연구판입니다.

이 문서는 현재 코드가 실제로 계산하고 표시하는 내용을 설명합니다. Kidze의 원본 소스를 복원한 지표가 아니라, 관찰한 차트를 바탕으로 만든 독립 구현입니다. 특히 분홍 계열과 일부 수명주기 규칙은 연구 후보입니다. 표시가 같다는 사실만으로 원본 규칙이나 매매 성과가 검증된 것은 아닙니다.

## 1. 먼저 알아둘 표시

| 표시 | 현재 코드에서의 뜻 |
|---|---|
| 큰 회색 `9` | Setup의 표시 숫자 9. 실제 raw9이거나, 반복 표시를 켠 경우 raw18·27…일 수 있습니다. |
| 큰 회색 `9*` | 실제 Setup 9이 완성되는 그 봉에서 perfection 조건도 충족했습니다. 별표는 문자 `*`가 맞습니다. |
| 큰 유색 `13` | 해당 색 계열의 카운트가 13까지 완성됐습니다. |
| `13x2` | 같은 계열·같은 방향의 서로 다른 출발점 2개가 같은 봉에서 13을 완성했습니다. 두 라벨을 하나로 모았습니다. |
| `13r` | Combo 계열 카운트가 진행되는 동안 같은 방향 raw Setup 18 이상이 한 번이라도 관찰됐다는 주석입니다. |
| `13rx2` | 동시 완성 출발점이 2개이며, 그중 적어도 하나에 `r` 조건이 있었습니다. 두 출발점 모두 `r`이라는 뜻은 아닙니다. |
| 아주 작은 유색 `1`~`12` | 카운트다운의 중간 진행 숫자. 기본 설정에서는 숨깁니다. |
| 아주 작은 `+8`, `+13` | 기본 카운트 조건은 통과했지만 추가 자격 조건을 통과하지 못해 해당 숫자를 보류했습니다. 기본 설정에서도 `+13`이 보일 수 있습니다. |
| 작은 회색 `1`~`8` | Setup 중간 숫자. `Setup display | only 9`를 끄면 나타납니다. |
| 작은 유색 `x` | 일부 취소 경로의 표시. 기본 설정에서는 숨깁니다. 모든 출발점 교체를 이 문자로 표시하는 것은 아닙니다. |

13의 색은 설정에서 바꿀 수 있습니다. 아래 설명은 기본 색 기준입니다. 위쪽 표시는 SELL 방향 카운트, 아래쪽 표시는 BUY 방향 카운트입니다. 방향명은 코드의 분류이며 그 자체가 주문이나 수익 보장은 아닙니다.

### BTCUSD 2주봉의 분홍 `13x2`

CRYPTO:BTCUSD 2주봉의 2024-12-16 봉에서는 분홍 Aggressive Combo 후보의 SELL 카운트다운 2개가 함께 완료됐습니다. 실제 라벨 툴팁에 표시된 출발점은 2021-11-08 00:00 UTC와 2024-01-29 00:00 UTC입니다. 두 날짜는 각 카운트가 채택된 Setup 9 봉의 시작 시각입니다. 기본 `Independent` 모드는 새로운 Setup 9에서 시작한 카운트를 기존 카운트와 함께 보존할 수 있으므로 이런 집계가 생깁니다.

`x2`는 두 배 강한 신호, 승률 2배, 26카운트, 서로 다른 두 계열의 합을 뜻하지 않습니다. 같은 계열의 출발점들이 같은 가격 자료를 공유하므로 독립적인 두 증거라고 가정할 수도 없습니다. 라벨에 마우스를 올리면 각 출발점의 UTC 시작 시각과 봉 번호를 확인할 수 있습니다. 위 두 출발 날짜는 2026-10-31에 해당 차트의 툴팁에서 확인했습니다.

차트에 적힌 날짜는 보통 그 봉의 시작 날짜입니다. 이 코드는 봉 마감 후에 신호를 확정하므로 2주봉 시작일에 이미 신호를 알 수 있었던 것으로 해석하면 안 됩니다.

## 2. `9`와 `9*`를 정확히 읽기

Setup은 종가를 4봉 전 종가와 비교하는 연속 카운트입니다. BUY는 현재 종가가 4봉 전보다 낮아야 하고, SELL은 높아야 합니다. 새 연속 카운트의 시작에는 반대 상태에서 넘어오는 엄격한 price flip도 요구합니다. 같은 가격은 해당 비교를 통과하지 않습니다. 조건이 깨지면 그 방향의 raw Setup은 0이 됩니다.

실제 raw9이 되면 Setup 9입니다. 이때 적용되는 별표 조건은 다음과 같습니다.

| 방향 | 현재 코드의 `9*` 조건 |
|---|---|
| BUY | Setup 8 또는 9의 저가 중 하나가 Setup 6과 7의 저가 모두 이하: `min(low8, low9) <= min(low6, low7)` |
| SELL | Setup 8 또는 9의 고가 중 하나가 Setup 6과 7의 고가 모두 이상: `max(high8, high9) >= max(high6, high7)` |

별표가 없는 실제 raw9은 그 시점에서 이 조건을 충족하지 않은 것입니다. 현재 구현은 9 이후에 perfection이 생겼다고 과거 9을 나중에 `9*`로 바꾸지 않습니다. 별표 유무는 카운트다운 시작을 걸러내는 조건으로 사용하지 않습니다. 출발점 정책이나 작은 Setup 거부 설정에 따라 새 카운트의 채택 여부는 별도로 결정됩니다.

기본값 `Display raw Setup counts as repeated 1-9`가 켜져 있으면 내부 raw10~18을 다시 1~9로 표시합니다. 그래서 두 번째 9은 raw18, 세 번째 9은 raw27입니다. 이 반복 9은 새 Setup 9 출발점이 아니며 `9*`도 붙이지 않습니다. 회색 9의 툴팁에 있는 `raw` 숫자로 구별할 수 있습니다.

## 3. 아주 작은 빨간 숫자가 보이는 이유

우선 숫자 앞의 작은 `+`를 확인하십시오. 기본값은 중간 카운트 숨김, 보류 표시 켜짐이므로 기본 설정을 그대로 사용했다면 작은 빨간 표시가 `+13`일 가능성이 있습니다. 실제 표시를 특정하려면 마우스를 올려 계열과 출발점을 확인하거나 설정의 중간 숫자 표시 여부를 함께 확인해야 합니다.

| 종류 | 표시가 생기는 조건 | 그 시점의 상태 |
|---|---|---|
| 빨강 `1`~`12` | `Show intermediate countdown numbers` 켜짐 | Sequential에서 해당 카운트를 실제로 채택했습니다. |
| 빨강 `+13` | 13의 기본 비교 통과, `13 vs 8` 자격 조건 실패 | 카운트는 12에 머물고 다음 적격 봉을 기다립니다. 완료 13이 아닙니다. |
| 빨강 `+8` | 8의 기본 비교 통과, `8 vs 5` 자격 조건 실패 | 카운트는 7에 머뭅니다. 이 자격 조건은 기본값이 꺼져 있습니다. |

BUY의 13vs8은 13 후보 봉의 저가가 카운트 8봉의 종가 이하여야 하고, SELL은 고가가 카운트 8봉의 종가 이상이어야 합니다.8vs5도 같은 방식으로 8 후보 봉의 꼬리 가격을 카운트 5봉의 종가와 비교합니다. 기본 비교 자체가 실패한 모든 봉에 `+13`을 찍는 것은 아닙니다.

화면을 간결하게 하려면 Display에서 중간 숫자와 보류 표시를 각각 끌 수 있습니다. 두 설정은 서로 독립적입니다. 숫자를 숨겨도 계산은 계속됩니다.

## 4. 색 계열과 계산의 차이

| 기본 색 / 약자 | 계열 | 기본 활성화 | 주요 차이 |
|---|---|---|---|
| 빨강 / `S` | Sequential | 켜짐 | 1~12는 종가를 2봉 전 꼬리 가격과 비교. 마지막 13은 기본적으로 시가 또는 종가를 허용합니다. |
| 주황 / `AS` | Aggressive Sequential | 꺼짐 | 종가 대신 저가·고가를 사용합니다. Sequential 계열의 추가 자격 조건을 별도 설정합니다. |
| 보라 / `C` | Combo | 켜짐 | 진행 기준이 직전 채택 카운트봉의 종가입니다.1~10은 여러 비교를 함께 적용하고 11~13은 기본적으로 완화합니다. 마지막 13만 기본 Wick 후보입니다. |
| 분홍 / `AC*` | Aggressive Combo 후보 | 켜짐 | 전 카운트가 꼬리 가격 기준이며 진행 기준도 직전 채택 꼬리입니다.1~10은 추가 비교,11~13은 기본 완화입니다. |

BUY 비교는 낮은 가격 쪽, SELL은 높은 가격 쪽입니다. 카운트다운은 조건을 만족한 봉만 증가하므로 13개 봉이 연속일 필요가 없습니다. Setup의 연속 9봉 조건과 구분하십시오.

Sequential BUY 1~12의 기본 비교는 `close <= low[2]`, SELL은 `close >= high[2]`입니다. 기본 마지막 13은 이 비교에 시가도 허용합니다.13 vs 8 추가 조건은 기본 켜짐,8vs5는 꺼짐입니다.

일반 Combo의 초기 1~10은 BUY의 경우 현재 종가가 직전 채택 종가 이하,2봉 전 저가 이하, 직전 봉 종가보다 낮아야 하고 현재 저가는 직전 봉 저가 이하여야 합니다. SELL은 반대 비교입니다. 첫 카운트는 직전 채택 값이 없으므로 그 진행 비교를 생략합니다. 기본적으로 11~13은 직전 채택 종가와의 진행 비교만 남깁니다. 마지막 13의 가격 선택에 따라 시가나 꼬리도 비교하지만, 일반 Combo가 저장하는 진행 기준은 계속 실제 종가입니다.

분홍 후보의 초기 1~10은 BUY의 경우 저가가 직전 채택 저가 이하,2봉 전 저가 이하, 직전 봉 저가보다 낮아야 합니다. SELL은 고가로 반대 비교합니다. 기본 11~13은 직전 채택 꼬리와의 진행 비교만 적용합니다. 일반 Combo의 마지막 13만 Wick으로 바꾸는 것과 분홍 후보는 같은 계산이 아닙니다.

Combo 두 계열은 Setup 9가 확정될 때 Setup 1~9 구간을 한 번 재계산하여 출발시킵니다. 그 과거 구간에서 1~9를 표시하는 옵션을 켜더라도, 그 값이 처음 알려지는 시점은 Setup 9 마감입니다. 이 과거 진행 숫자를 보려면 `Show retrospective Combo1-9 numbers`와 `Show intermediate countdown numbers`를 함께 켜야 합니다. `Show qualifier deferrals (+8 / +13)`만 켜서 Combo 과거 진행 숫자가 나타나는 것은 아닙니다. 현재 코드에서 `+8`·`+13` 보류는 Sequential 두 계열에서만 생성하며, Combo 두 계열에는 이 보류 조건이 없습니다.

## 5. `r`, 출발점 유지와 취소

`13r`의 `r`은 현재 구현의 refresh 주석입니다. 진행 중 같은 방향 raw Setup이 18이상인 상태를 만나면 그 카운트에 기록이 남고, 이후 Combo 또는 분홍 Combo 후보가 13으로 완성될 때 표시합니다. raw가 나중에 끊겨도 기록은 유지됩니다. `Annotate Combo13r after a raw Setup18+`를 끄면 주석만 숨깁니다.

이 `r`은 실제 카운트 재시작을 실행하지 않습니다. 더 강한 반전 신호라고 검증한 결과도 없습니다. 원본 Kidze의 `r` 의미와 동일하다고 확정하지 않았습니다.

### 같은 방향 출발점 정책

| 옵션 | 작동 |
|---|---|
| `Independent` — 기본 | 채택한 실제 Setup 9마다 별도 카운트를 유지합니다. `13xN`이 생길 수 있습니다. |
| `Keep active` | 같은 계열·방향의 카운트가 진행 중이면 새 출발점을 채택하지 않습니다. 진행 중인 것이 없으면 새 출발이 가능합니다. |
| `Recycle range` | 진행 중이면 새 Setup 첫 9봉 범위가 이전 채택 Setup의 확장 범위 대비 설정 비율 안에 들어갈 때 기존 카운트를 새것으로 바꿉니다. 진행 중인 것이 없으면 비율만으로 막지 않습니다. |
| `Newest` | 새 출발점을 채택하면 같은 계열·방향의 기존 카운트를 제거합니다. |

별도로 `Reject a smaller new Setup9`를 켜면 이전 채택 Setup보다 범위가 작은 새 Setup을 거부할 수 있습니다. 이 비교는 이전 13이 끝난 뒤에도 적용됩니다. 이전 기준 범위는 그 연속 Setup이 지속되는 동안 당시까지 알려진 가격으로 확장합니다. 거부된 Setup은 새 기준으로 삼지 않습니다.

기본적으로 반대 방향의 실제 raw9이 나오면 기존 반대 방향 카운트를 먼저 취소합니다. 같은 봉에서 13도 완성될 수 있더라도 취소를 먼저 처리합니다. 화면 반복 9인 raw18은 이 취소나 새 출발을 발생시키지 않습니다.

TDST 취소와 raw22 재시작은 별도 연구 옵션이며 기본 꺼짐입니다. TDST 취소는 BUY의 현재 true low가 출발 Setup의 true high를 넘어가거나, SELL의 현재 true high가 출발 Setup의 true low보다 낮아질 때 적용합니다. true high/low는 현재 고가·저가와 이전 종가를 함께 고려합니다. raw22 재시작은 Sequential·Aggressive Sequential에만 적용하며, raw22봉에서 새로 카운트합니다. 새 Setup 9를 만들거나 Combo 과거 구간을 재계산하지 않습니다.

## 6. 모든 설정과 기본값

설정창의 영문 이름과 대응시켰습니다. 켜짐/꺼짐은 새로 추가한 지표의 코드 기본값입니다. 이미 차트에 저장된 인스턴스의 설정은 다를 수 있습니다.

### 1 | Families

| 설정 | 기본값 | 역할 |
|---|---|---|
| Sequential \| red | 켜짐 | 빨강 계열 계산·표시 활성화 |
| Combo \| purple | 켜짐 | 보라 계열 활성화 |
| Aggressive Sequential \| orange | 꺼짐 | 주황 계열 활성화 |
| Aggressive Combo candidate \| pink | 켜짐 | 분홍 실험 후보 활성화 |

### 2 | Sequential

| 설정 | 기본값 | 역할 |
|---|---|---|
| Sequential final13 price | `Open or Close` | 마지막 13의 기본 비교 가격. `Close` / `Open or Close` / `Wick` |
| Sequential 13 vs 8 qualifier | 켜짐 | 13 후보 꼬리와 카운트 8 종가 추가 비교 |
| Sequential 8 vs 5 qualifier | 꺼짐 | 8 후보 꼬리와 카운트 5 종가 추가 비교 |
| Final13 tolerance \| current minimum ticks | 0 | 마지막 13 기본 비교에 허용할 현재 최소 틱 수.0~10. 추가 자격 비교에는 적용하지 않으며 Aggressive Sequential에도 적용됩니다. |

### 3 | Combo

| 설정 | 기본값 | 역할 |
|---|---|---|
| Combo final13 price \| experimental default | `Wick` | 일반 Combo의 마지막 13 비교 가격. 실험 기본값이며 전 카운트를 꼬리로 바꾸지는 않습니다. |
| Relax ordinary Combo counts 11-13 | 켜짐 | 일반 Combo 11~13의 추가 비교 완화 |
| Combo final13 tolerance \| current minimum ticks | 0 | 일반 Combo 마지막 13의 진행 비교 허용 틱 수.0~10 |
| Annotate Combo13r after a raw Setup18+ | 켜짐 | 보라·분홍 완료 13의 `r` 주석 표시 |

## 7. 라벨의 크기, 가격 간격과 꼬리 겹침 보정

Setup의 표시 9와 완료 13은 같은 `size.large`입니다. 유색 중간 카운트와 보류 표시는 `size.tiny`, Setup의 9 외 숫자는 `size.small`입니다. 글자 크기와 신호 계산은 서로 별개입니다.

이번 수정에서는 모든 라벨의 기존 x·y 기준 좌표를 유지하면서, 글자가 그 좌표에서 펼쳐지는 방향을 바꿨습니다. BUY 라벨은 저가 아래의 기준점에 투명한 `label.style_label_up`을 사용하여 글자가 아래로 펼쳐지게 합니다. SELL 라벨은 고가 위의 기준점에 투명한 `label.style_label_down`을 사용하여 글자가 위로 펼쳐지게 합니다. 배경과 연결부는 투명하므로 기존처럼 숫자만 보입니다. 완료 13뿐 아니라 Setup 숫자, 중간 카운트, 보류 및 취소 표시에도 같은 방향 배치를 적용합니다.

기존의 `label.style_none`에서는 기준 좌표 주변에 글자가 걸쳐질 수 있어, 좌표 자체가 꼬리 밖이어도 큰 숫자가 해당 봉의 꼬리 쪽으로 겹칠 수 있었습니다. 새 배치는 숫자 본문을 해당 봉의 꼬리 반대 방향으로 펼쳐 그 겹침을 줄이는 방법입니다. 신호 조건·카운트·발생 봉·문자 내용·색·글자 크기와 입력 기본값은 유지합니다. Pine에서 라벨 스타일은 기준점 대비 표시 위치에도 영향을 줍니다. [TradingView 공식 설명: Text and shapes](https://www.tradingview.com/pine-script-docs/visuals/text-and-shapes/)

완료 13에는 이전에 도입한 ATR 간격과 가격 대비 상한을 유지합니다. 기본색 기준 빨강 1.5%, 주황 3%, 보라 4.5%, 분홍 6%가 해당 봉의 고가·저가에서 라벨 기준점까지의 최대 간격입니다. 정확히는 기준 가격의 절댓값 대비 비율입니다. 실제 ATR 간격이 작으면 기준점은 더 가깝습니다. 이 비율은 라벨의 기준점 상한이며, 글자 외곽 전체가 그 비율 안에 들어간다는 뜻은 아닙니다. 글자는 기준점에서 바깥 방향으로 더 펼쳐집니다. Setup 9와 중간 숫자에는 이 완료 13 상한을 새로 적용하지 않았습니다.

원래 큰 낙폭 뒤에는 ATR이 현재 저가에 비해 크게 남을 수 있었습니다. 특히 로그 차트에서 저가에서 큰 ATR을 빼면 라벨 가격이 0에 가까워져 멀리 떨어져 보일 수 있어 이전에 가격 비율 상한을 추가했습니다. 이번 방향 배치는 그 좌표 계산을 그대로 유지한 표시 수정입니다.

이웃 봉의 긴 꼬리나 여러 라벨끼리의 겹침을 찾아 재배치하는 알고리즘은 아닙니다. 따라서 매우 좁은 차트나 모든 확대·축소에서 일정한 픽셀 간격과 모든 종류의 겹침 해소를 보장하지 않습니다.

## 8. 상태표 읽기

| 항목 | 뜻 |
|---|---|
| `Buy runs / count`, `Sell runs / count` | 활성 출발점 수 / 그중 가장 높은 현재 카운트. 예: `2 / 11`은 2개가 진행 중이며 최고 진행이 11입니다. 총 카운트 합이 아닙니다. |
| `off` | 해당 계열 비활성화 |
| `Final13` | 마지막 13 비교 가격. 일반 Combo의 `Wick*` 별표는 실험 설정 주석이며 Setup의 `9*`와 다른 뜻입니다. |
| `Raw Setup` | 1~9로 반복 표시하기 전의 실제 연속 Setup 카운트 |
| `Independent` 등 | 선택한 출발점 정책 |
| `Dropped N` | 최대 활성 출발점 수를 넘어 제거한 누적 수. 표시 라벨 수 제한으로 지운 숫자와 다릅니다. |
| `CAP WARNING` | 출발점 용량 초과 제거가 한 번 이상 있었음 |
| `Small N` | 작은 Setup 거부 옵션에 의해 거부한 계열별 시도의 누적 수. 하나의 Setup이 여러 계열에서 거부되면 각각 더해집니다. |
| `* candidate` | 분홍 계열이 연구 후보임을 알리는 주석. Setup perfection 별표와 다릅니다. |

용량 제한은 실행량 관리 선택이며 원본 DeMARK 규칙이라는 뜻이 아닙니다. 표시 라벨 수 제한도 계산 중인 출발점 수와 별개입니다.

## 9. 봉 마감, 과거 표시, 알림

모든 Setup·카운트 상태 변화와 완료 13 조건은 현재 차트 봉의 마감 후에 확정합니다. 진행 중인 일봉·2주봉의 움직임을 임시 13으로 표시하지 않습니다. `request.security`, lookahead, varip를 사용하지 않습니다.

과거 Combo 숫자를 뒤늦게 표시하는 옵션은 별도 주의가 필요합니다. 과거 봉 위에 숫자가 그려졌더라도 Setup 9 마감 전에 그 값을 실시간으로 알았다고 볼 수 없습니다. 과거 구간에 대한 알림을 소급해서 발생시키지 않습니다.

코드는 아래 9가지 알림 조건을 제공합니다. 차트에 지표를 추가하는 것만으로 알림을 자동 생성하지는 않습니다.

- Sequential Buy13 / Sell13
- Aggressive Sequential Buy13 / Sell13
- Combo Buy13 / Sell13
- Aggressive Combo candidate Buy13 / Sell13
- Any13

`13x2`는 해당 계열·방향 알림 조건을 같은 봉에서 두 번 만드는 방식이 아닙니다. 완료 수가 0보다 큰지를 조건으로 사용합니다. 알림을 설정한다면 봉 마감 기준을 사용하십시오. TradingView는 알림을 만들 때 스크립트·입력값·종목·시간주기를 별도 사본으로 저장합니다. 이후 차트나 코드를 바꿔도 기존 실행 알림은 자동으로 갱신되지 않습니다. 새 조건을 반영하려면 원하는 버전과 설정으로 알림을 다시 만들어야 합니다. [TradingView 공식 설명: Alerts](https://www.tradingview.com/pine-script-docs/concepts/alerts/)

`kidze_td_research_v6.pine`의 전체 내용을 TradingView Pine 편집기에 붙여넣고 저장·차트 적용하면 됩니다. 첫 줄은 `//@version=6`입니다. Python 파일은 연구 검증용이며 지표 실행에 필요하지 않습니다. 기본 설정과 일반 캔들로 먼저 관찰하십시오.

코드 기본값과 기존 차트 인스턴스의 저장 설정이 다를 수 있습니다. 같은 티커 이름이어도 거래소·가격 피드·거래 세션·봉 시작 기준·로드된 과거 구간·수정된 가격 자료가 다르면 결과가 달라질 수 있습니다. 차트의 표시 시간대만 바꾸는 것은 표시 시각의 변경이며, 이 코드의 OHLC 비교 계산을 바꾸지 않습니다. 툴팁의 출발 시각은 UTC로 고정해 표시합니다. 일반 캔들과 Heikin Ashi 같은 가공 캔들도 같은 입력 자료가 아닙니다. 앞선 연구의 Python 참조 구현에서는 보존된 952봉과 17개 테스트를 사용했습니다. 알려진 출발점 기준의 끝 위치 20개 중 18개가 맞았고, Sequential의 SUI 관찰일 2025-02-26 대 기본 계산 2025-03-03, SHIB 관찰일 2025-02-28 대 기본 계산 2025-03-01은 맞지 않았습니다.
